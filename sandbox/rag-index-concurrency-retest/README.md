# 双星索引井：RAG 索引并发复测

知识库只上传了一次文档，但两个索引 Worker 几乎同时读到了同一条 `pending` 任务。它们都认为自己领取成功，并各写入了一套 chunks，最终让检索结果出现重复引用。

这不是第 5 章“双击保存”案件的换皮：前端没有重复请求，竞争发生在两个后端工作进程之间。你需要用上传记录、Worker 时间线、数据库快照和仓库代码回答四个问题：

1. 谁产生了重复工作？
2. 为什么普通的“先查再改”挡不住并发领取？
3. 唯一约束能保护什么，不能替代什么？
4. 任务状态和 chunks 为什么需要处在清晰的事务边界内？

运行：

```bash
npm test
```

初始代码应得到 `2 passed, 1 failed`。失败用例就是待修复的并发领取行为。
