# Frontend Regression Proof Arena

前端工程路线第 5 关“测试怎么证明修好了”的独立练习沙盒。

这关的剧情是：任务列表的筛选功能曾经出过回归，用户选择 `status=blocked` 后，页面却还混着显示已完成任务。Agent 交付了一份“全部通过”的修复报告，但前端测试仲裁官不接受空口承诺。你要判断这份验收证据是否可信：

- 有没有先复现旧问题；
- 有没有单元测试证明小逻辑；
- 有没有集成测试证明真实流程；
- 有没有手动测试步骤、期望结果和实际结果；
- 测试报告是不是对应当前代码，而不是旧代码的过期报告；
- 有没有写清回归风险和面试复盘表达。

## 手动运行

```bash
npm test
```

测试只使用 Node 内置模块，不联网、不读取真实项目。运行后会在本目录生成 `test-results.json`，学习应用只读取这个固定报告。

初始状态下测试会失败，这是本章练习入口：用户需要让报告校验器真的拒绝不可信证据，而不是把“有通过截图”和“Network 绿了”当成修好了。
