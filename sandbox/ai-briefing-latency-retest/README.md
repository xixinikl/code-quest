# 晨星时序港：AI 晨报首字延迟复测

客服主管打开当天晨报后，页面外壳很快出现，摘要正文却要等三秒多才开始流出。第二次打开同一团队、同一天的晨报仍然一样慢。

这不是第 6 章“项目列表一次渲染 2500 行”的原题换皮。这里前端只渲染 24 条摘要，真正的等待集中在服务端调用模型到首字返回的阶段；第二次访问继续等待，是因为缓存键错误地混入了每次都变化的 `requestId`。

先沿固定证据回答：

1. 页面资源、接口等待、下载和浏览器渲染分别用了多久？
2. `Server-Timing` 里最长的是数据查询还是模型首字？
3. 第二次业务条件相同，为什么仍然是 `MISS`？
4. 修复缓存后，如何证明不是把过期晨报错误地发给别的团队或日期？

运行：

```bash
npm test
```

初始代码应得到 `2 passed, 1 failed`。失败用例证明相同业务查询没有复用已经生成的晨报。
