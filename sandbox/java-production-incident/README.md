# 事故回声塔：线上故障如何从日志走到回滚

Java 后端路线第 5 关“线上故障如何判断和止血”的独立练习沙盒。

这关的剧情是：事故回声塔连续响起警报，值班工程师把日志、指标和稳定版本交到你手里。他要你核对：

- 错误率和 P95 延迟是否超过影响判断阈值；
- 请求 ID、时间窗口、异常堆栈和版本号是否能对齐；
- 受影响用户和业务范围是否已经确认；
- 止血动作、回滚条件和稳定版本是否写清楚；
- 回滚后冒烟测试和恢复证据是否可复测；
- 事故复盘是否能讲清楚取舍，而不是只说“数据库有问题”。

## 手动运行

```bash
npm test
```

测试只使用 Node 内置模块，不联网、不访问真实系统。运行后会生成 `test-results.json`，学习应用只读取这份固定报告。

初始状态下测试会失败，这是本章练习入口：用户需要让上线门禁真的拦住不安全上线，而不是把“构建成功”误认为“可以上线”。
