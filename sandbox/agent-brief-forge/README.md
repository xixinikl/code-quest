# Agent Brief Forge

第 12 章“Agent 任务怎么写”的独立练习沙盒。

这关的剧情是：委托书锻造师收到一张很危险的任务纸条：“帮我把项目优化一下，顺便修 bug。”这类委托会让 Agent 猜范围、乱改文件、漏验收，最后你也不知道它到底完成了什么。

你要把任务锻造成工程委托书：

- 背景：现在发生了什么，已有证据是什么；
- 目标：要达成什么可观察结果；
- 约束：哪些文件、命令、数据和边界不能碰；
- 验收：跑哪些命令、走哪条浏览器路径、看到什么结果；
- 风险：哪些情况还没覆盖，失败时怎么回退；
- 交付格式：Agent 最后要写摘要、验证证据、风险和后续。

## 手动运行

```bash
npm test
```

测试只使用 Node 内置模块，不联网、不访问真实系统。运行后会生成 `test-results.json`，学习应用只读取这份固定报告。

初始状态下测试会失败，这是本章练习入口：用户需要让委托书校验器真的拒绝空泛任务，而不是把“字数够多”当成清晰。
