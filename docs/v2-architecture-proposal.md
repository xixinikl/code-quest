# V2 数据与架构提案

## 已确认方案

采用本地全栈应用，而不是继续使用纯前端：

```text
React 学习界面
    ↓ HTTP API
本地 Node 服务
    ├── SQLite 学习记录数据库
    ├── 关卡与评分规则
    └── 固定路径测试报告读取器
             ↑
       用户手动运行独立练习项目测试
```

## 数据事实源

SQLite 保存：

- 学习者本地身份；
- 诊断会话；
- 关卡尝试与每一步原始回答；
- 提示使用情况；
- 自动测试结果；
- rubric 评分及理由；
- 能力证据；
- 复测安排；
- 自定义词典。

localStorage 只允许保存主题、侧栏状态等可丢失的界面偏好。

## 为什么首版后端仍使用 SQLite

- 用户当前是单机个人使用，不需要 PostgreSQL 的多用户并发与运维。
- 数据是结构化、可查询和可备份的真实记录，不再是浏览器缓存。
- 同时可以把“SQLite 与 PostgreSQL 的差别”变成应用自身可观察的学习材料。
- 数据访问层保持边界，未来出现账号、云同步或多用户需求时再迁移 PostgreSQL。

## 沙盒边界

- 每个场景使用独立目录和独立数据库，绝不读取 CanvasStorm 或其他用户项目。
- Web 应用和本地学习服务不执行任何 shell 命令，也不接受命令字符串。
- 测试由用户在终端中手动运行；应用只读取固定沙盒内结构已验证的测试报告。
- 第一版不提供自动重置。种子文件只读保存在 `fixtures/`，恢复由用户明确复制，避免应用删除文件。
- 沙盒日志去除环境路径和秘密后才能写入学习记录。
- 服务只监听 `127.0.0.1`，不对局域网或互联网开放。

## API 初稿

- `POST /api/diagnostic-sessions`：开始真实诊断。
- `POST /api/attempts`：记录关卡尝试。
- `PATCH /api/attempts/:id/steps/:stepId`：保存逐步回答和提示。
- `POST /api/attempts/:id/verify`：读取固定路径的测试报告，绝不执行命令。
- `POST /api/attempts/:id/submit`：根据证据规则结算。
- `GET /api/evidence`：查看能力证据和评分理由。
- `GET /api/reviews/due`：获取到期变式复测。
- `GET /api/learning-backup`：导出本地 SQLite 学习记录。
- `POST /api/learning-backup/import`：从本地 JSON 合并恢复白名单学习记录表。

## 回滚与迁移

- V1 localStorage 进度不直接转换为能力等级，因为它没有可信证据。
- 首次进入 V2 时可保留旧 XP 为“纪念经验”，但能力统一标记为 L0 未诊断。
- 数据库迁移必须可重复执行；开发阶段可备份 SQLite 文件后升级。
- 任一沙盒命令越出允许列表、修改真实项目或无法可靠恢复时，立即停止该方案。

## 重大未知项

1. 编辑方式：已确认使用用户自己的编辑器和终端，操作独立沙盒。
2. AI 边界：第一纵向切片不接入 AI 自动评分；使用确定性验证、透明 rubric 和复测。
3. 运行范围：已确认只做本地个人版，不包含云账号与远程部署。
