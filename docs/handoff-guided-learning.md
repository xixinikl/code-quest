# 引导式教学交接事实

## 用户的原始目标

用户只有少量代码基础，正在使用 Agent 开发软件。他希望提升到能够：

- 看懂 Agent 在说什么；
- 知道复杂项目大致如何推进；
- 能提出更好的任务；
- 能判断实现和验收是否可信；
- 在真实项目中逐步形成开发经验。

用户不希望靠看长课程，也不希望学习内容污染真实项目对话。他偏好“游戏闯关 + 干中学”，但闯关必须产生真实进步。

## 已经否定的产品做法

V1 使用自评、明显的单选题和 XP 晋级。用户准确指出：

- 错误选项太明显，可以凭常识猜中；
- 系统不了解真实水平；
- UI 验收通过不代表学会；
- localStorage 不是可靠学习记录。

因此 V2 已经改成真实项目材料、自由回答、手动测试与 SQLite 证据记录。

## 当前最新用户反馈

用户进入第一关的真实代码区域后反馈：

> 代码看不懂时，完全不知道从何下手；没有一点点教学环节，只是单纯测试；这里对我来说是一个坎。

随后明确确认需要：

> 引导性，引导式教学。

这说明当前 V2 仍存在关键断层：

- 系统会采集“不会”的证据，却没有先帮助用户建立理解；
- 从业务故障直接跳到整份代码，认知负担过高；
- 材料真实，但缺少阅读路径、概念前置和共同示范；
- “测试”与“教学”混在一起，容易让初学者把不会理解成失败；
- 真实不等于一次性把真实复杂度全部压给用户。

## 新产品原则

### 教学、陪练、实战必须分开

| 模式 | 目的                 | 是否允许完整讲解 | 是否记录提示依赖 | 是否产生能力证据    |
| ---- | -------------------- | ---------------- | ---------------- | ------------------- |
| 教学 | 建立当前任务所需认知 | 允许             | 否               | 否                  |
| 陪练 | 在逐渐减少帮助时练习 | 分级允许         | 是               | 只能形成 L1/L2 候选 |
| 实战 | 检查能否独立迁移     | 不提供即时答案   | 是               | 可形成更高等级候选  |

### 每次展示代码前必须回答五件事

1. 这段代码位于整个项目的哪里？
2. 当前只需要看哪几行？
3. 输入是什么，输出是什么？
4. 哪些内容现在可以忽略？
5. 看完后只需要完成什么小动作？

### 逐渐撤掉辅助

正确节奏是：

```text
我讲给你看
→ 我带你做
→ 你做、我提示
→ 你独立完成
→ 换一个表象再做
```

不是：

```text
给代码 → 让用户猜 → 跑测试 → 判定水平
```

## 当前数据与安全不变量

- 学习记录事实源是 `.data/code-quest.sqlite`。
- localStorage 只能保存可丢失 UI 偏好，不能保存能力证据。
- API 不接受命令，不导入 `child_process`。
- 服务只监听 `127.0.0.1`。
- 只允许读取 `server/scenarios.ts` 注册的沙盒文件。
- 路径必须经过真实路径边界检查，拒绝符号链接逃逸。
- 测试由用户手动运行；Web/API 只读 `test-results.json`。
- 旧报告、结构错误报告和源码指纹不匹配报告必须失效。
- 不读取、修改或上传 CanvasStorm。

## 可保留与需要重构的部分

可保留：

- 本地 API 与 SQLite 事实源；
- 安全沙盒与测试报告机制；
- 无提示基线；
- 提示记录与透明“候选证据”措辞；
- 当前真实材料和视觉语言。

需要重构：

- `src/App.tsx` 中从基线直接进入材料调查的流程；
- 把整份文件直接展示给初学者的代码阅读方式；
- 全局提示等级与教学帮助的混淆；
- 当前即时文字迁移题；
- 缺少“我没看懂”分支和前置知识补偿。

## 未授权范围

本次不要做：

- 新增第二、第三个业务场景；
- 接入 AI 自动评分或外部 API；
- 云账号、部署、排行榜、付费；
- 自动执行 shell、Docker 或任意代码；
- 重写数据库驱动或迁移 PostgreSQL；
- 宣称真人学习验收通过；
- 合并到 `main`。
