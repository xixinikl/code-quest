# 技术决策

## ADR-001：独立本地优先单页应用

- 状态：采用
- 决策：使用 React + TypeScript 单页应用，进度保存于 localStorage。
- 原因：满足“不污染真实项目会话”，无需账号或服务器即可形成完整学习闭环。
- 代价：跨设备不同步，清理浏览器数据会丢失进度。
- 替代：全栈账号系统；首版收益不足以覆盖隐私、认证和运维成本。

## ADR-002：固定策划关卡而非即时 AI 生成

- 状态：采用
- 决策：首版关卡内容作为版本化代码数据维护。
- 原因：离线可用、可测试，知识质量与计分稳定，也不会产生 API 费用。
- 后续触发：固定关卡闭环验证有效后，再评估可选 AI 个性化，不得上传源码。

## ADR-003：视觉雷达采用原生 SVG

- 状态：采用
- 决策：不用图表依赖，使用可访问的 SVG 绘制五维雷达。
- 原因：首版图形简单，减少包体与供应链面。

## ADR-004：证据式学习取代 XP 晋级

- 状态：采用，替代 V1 的自评与单选晋级。
- 决策：保存原始回答、提示、测试结果和评分理由；XP 不再表示能力等级。
- 原因：一次识别或明显单选无法证明独立操作与知识迁移。
- 限制：第一纵向切片只产生 L1/L2 候选证据；没有延迟变式复测时不得判定 L3。

## ADR-005：保守安全的本地沙盒

- 状态：采用。
- 决策：用户在自己的编辑器和终端操作固定练习项目；Web/API 不执行 shell，只读注册路径的结构化测试报告。
- 原因：真实练习需要代码与测试，但应用不应获得控制用户电脑的广泛权限。
- 代价：自动化较少，用户需要手动运行测试。
