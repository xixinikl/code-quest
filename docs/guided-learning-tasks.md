# 引导式教学实施任务

## 分支与工作流

- 基线：用户提供的冻结 `main` 提交。
- 开发分支：`feat/guided-learning-bridge`。
- 必须按 `$standard-project-workflow` 的 M 级流程推进。
- 每完成一个纵向切片就运行最便宜的相关验证。
- 不在分支完成后自行合并、推送、建 PR 或部署。

## G0：事实门禁

- [ ] 读取 `HANDOFF.md` 指定的全部文件。
- [ ] 确认工作区干净，当前分支不是 `main`。
- [ ] 运行冻结基线 `npm run verify` 并记录结果。
- [ ] 浏览现有 V2 主流程和第一关代码。
- [ ] 列出会修改的模块、数据表和测试。

停止条件：基线验证失败、冻结哈希不一致或发现未说明的用户改动。

## T1：冻结教学信息架构

- [ ] 把教学、陪练、实战定义成独立模式。
- [ ] 定义项目地图、概念卡、代码焦点、检查题和补课分支的数据结构。
- [ ] 明确哪些状态进入 SQLite，哪些只是 UI 临时状态。
- [ ] 建立旧尝试数据兼容策略。

验证：契约可以逐项映射 `guided-learning-spec.md` 的 12 条验收标准。

## T2：项目地图纵向切片

- [ ] 基线后进入项目地图。
- [ ] 展示前端、HTTP、路由、repository、SQLite 与刷新读取。
- [ ] 每个节点有职责、输入、输出和证据。
- [ ] 记录完成状态并支持刷新恢复。

验证：组件测试、API/存储测试、真实浏览器刷新路径。

## T3：四个微知识教学

- [ ] 内存数组。
- [ ] 数据库持久化副作用。
- [ ] HTTP 201 的证据边界。
- [ ] 数据访问层职责。
- [ ] 每项包含类比、当前项目例子、预测、即时解释。
- [ ] 教学查看答案不增加提示等级。

验证：教学记录与陪练提示在数据库中严格分开。

## T4：引导式代码导读

- [ ] 默认只显示当前 5～10 个重点行。
- [ ] 显示项目位置、输入、输出、忽略项和观察目标。
- [ ] 支持主动展开完整文件。
- [ ] 按前端 → 路由 → repository → 数据源不一致顺序导读。
- [ ] 内容来自可测试的数据模型，不散落在单个巨型组件。

验证：重点行范围、默认折叠和完整文件展开均有自动化测试。

## T5：“这里没看懂”补课分支

- [ ] 可选择术语、语法、项目位置、因果关系四类卡点。
- [ ] 每类提供短补课并返回原步骤。
- [ ] 不增加提示等级，不判定能力失败。
- [ ] 刷新后能恢复原位置。

验证：四个分支至少覆盖一个完整行为测试和一个负面测试。

## T6：共同示范与陪练

- [ ] 示例展示如何连接 Network、数据库与代码证据。
- [ ] 修改任务拆成可执行小动作。
- [ ] 三层陪练提示逐渐具体。
- [ ] 只有陪练提示增加依赖记录。
- [ ] 保留用户在自己编辑器和终端手动操作的安全模式。

验证：相同行为结果在零提示与三级提示下产生不同候选证据理由。

## T7：实战、解释与透明结算

- [ ] 完成教学/陪练前不能错误结算能力。
- [ ] 真实测试报告与源码指纹规则不退化。
- [ ] 解释 rubric 显示具体缺口，不以字数代替语义。
- [ ] 仍明确标注“尚未完成延迟迁移复测，不能判定 L3”。

验证：成功、测试失败、旧报告、源码不匹配、解释缺失均有行为证据。

## T8：分层验证

- [ ] 格式、Lint、TypeScript、测试、构建。
- [ ] 数据库从空库迁移和旧 schema 升级。
- [ ] API 成功与错误路径。
- [ ] 真实浏览器完整桌面路径。
- [ ] 360px 无横向溢出。
- [ ] 刷新恢复。
- [ ] 浏览器控制台无未解释错误。
- [ ] `child_process` 与任意命令入口安全扫描。
- [ ] standard-project-workflow 严格治理审计。

## T9：项目记忆与交接

- [ ] 更新 `docs/decisions.md` 与 `docs/debt.md`。
- [ ] 更新 `docs/v2-tasks.md`，准确区分工程通过与真人待验。
- [ ] 添加 changelog fragment。
- [ ] 输出功能分支 HEAD、diff、验证、风险和回滚。
- [ ] 不合并 `main`，等待原 Agent 审查。

## 建议提交拆分

仅在用户授权提交的前提下：

1. `docs(learning): define guided teaching contract`
2. `feat(learning): add project map and teaching state`
3. `feat(learning): add micro-lessons and guided code tour`
4. `feat(learning): separate coaching hints from teaching help`
5. `test(learning): cover guided journey and safety boundaries`

不要为追求提交数量拆出无法独立验证的半成品。
