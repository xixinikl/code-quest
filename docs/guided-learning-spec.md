# 第一关引导式教学需求契约

## 用户故事

作为看不懂完整项目代码的初学者，我希望系统先告诉我代码在项目中的位置、只看哪些行、每一行在做什么，并带我完成一个小动作；这样我能逐渐建立读代码的方法，而不是面对整份文件发懵。

## 本次范围

只改造现有 `canvas-save-persistence` 场景，在无提示基线与当前材料调查之间加入教学桥梁，并把后续流程明确分成教学、陪练和实战。

不增加新业务场景，不接入 AI，不改变手动运行测试的安全模式。

## 推荐学习流程

### 0. 无提示基线

保留现有三项自由回答。提交后封存，后续教学不得覆盖。

### 1. 项目地图

先不展示代码，用可视化数据流说明：

```text
用户点击
→ React 前端
→ POST /api/canvases
→ 后端路由
→ repository
→ SQLite
→ 刷新后 GET
```

每个节点回答：

- 它负责什么；
- 输入和输出是什么；
- 当前故障可能在哪些节点；
- 哪些证据可以观察它。

用户应能点击节点查看简短解释，但不得被要求背术语。

### 2. 当前任务所需微知识

只教四个概念：

1. 内存数组：进程活着时能看到，重启或重新查询数据库后不一定存在。
2. 数据库持久化：需要发生真实 `INSERT` 等副作用。
3. HTTP 201：表示接口声称创建成功，不自动证明数据库已写入。
4. 数据访问层：负责把业务对象真正写入或读出存储。

每个概念使用：

- 一个生活类比；
- 一个与当前场景直接相关的例子；
- 一个无需读代码的预测问题；
- 立即解释反馈。

教学问题不计入能力分，也不增加提示等级。

### 3. 引导式代码导读

首次不得直接展示整份文件。

每一步最多突出 5～10 行关键代码，同时显示：

- 文件在项目地图中的位置；
- 当前函数名；
- 输入；
- 输出；
- 现在忽略哪些 import、类型或框架细节；
- 本步只观察一个事实。

推荐导读顺序：

1. 前端只看 `fetch` 和 `response.ok`，理解前端为什么相信成功。
2. 路由只看 `repository.saveCanvas` 与 `return 201`。
3. repository 只看对象创建、`pendingCanvases.push` 和 `listCanvases` 的 SQL 查询。
4. 对照解释：写入内存数组，读取却来自 SQLite，形成数据源不一致。

允许用户展开完整文件，但完整文件不是默认视图。

### 4. 共同完成的示范

系统先示范如何从两份证据形成一句有效判断：

```text
Network 的 201 只能证明接口返回成功；
数据库 0 行说明持久化副作用没有发生；
因此下一步应检查路由返回 201 前是否执行了数据库写入。
```

示范后让用户从给定证据中自己连接下一条因果，不要求立即改代码。

### 5. 陪练

把修改拆成小动作：

1. 找出当前写入位置；
2. 判断写入目标是内存还是 SQLite；
3. 找到表字段；
4. 组合 `INSERT` 需要的值；
5. 在自己的编辑器中完成修改；
6. 手动运行测试。

陪练提示分三级，并记录依赖程度。教学阶段已经展示过的内容不能再次作为“使用提示”惩罚用户。

### 6. 独立实战

现有真实修复和测试阶段保留，但只能在教学与陪练完成后出现。

测试通过只证明行为正确，不能自动证明理解。

### 7. 解释与复盘

用户用自己的话解释：

- 原来的成功提示从哪里来；
- 刷新后的数据从哪里来；
- 两个数据源为什么不一致；
- 修复产生了什么真实副作用；
- 哪些测试证明成功路径和失败路径。

系统展示 rubric 缺口，不因为字数达标就判定理解。

### 8. 后续迁移

本分支可以为真正的延迟复测预留数据结构和入口，但不要用即时文字题冒充 L3。第二个可运行场景仍属于后续任务。

## “我没看懂”分支

每个教学步骤必须有显眼的“这里没看懂”入口。点击后：

- 不增加提示等级；
- 先询问具体卡点：术语、代码语法、项目位置还是因果关系；
- 跳转到对应的 1～3 分钟前置微课；
- 返回原步骤时保留上下文；
- 记录学习路径，但不记录为能力失败。

不得只弹出“请再读一遍”或直接展示完整答案。

## 内容模型要求

教学内容不能全部散落硬编码在一个巨型组件里。至少建立可测试的场景教学结构：

```ts
type TeachingStep = {
  id: string;
  mode: "teaching" | "coaching" | "assessment";
  title: string;
  goal: string;
  projectPosition?: string;
  concepts?: ConceptCard[];
  codeFocus?: CodeFocus;
  check?: LearningCheck;
  remediation?: RemediationPath[];
};
```

确切文件拆分由实现 Agent 根据现有代码决定，但 `src/App.tsx` 不应继续无限增长。

## 数据要求

- 保存当前教学步骤和已完成教学检查。
- 教学帮助与陪练提示必须分开存储。
- 原始基线不可被教学回答覆盖。
- 旧 V2 尝试数据需要安全兼容；无法兼容时必须设计迁移和回滚。
- 不允许重新把学习记录放回 localStorage。

## 可执行验收标准

1. 基线提交后，用户先看到项目地图，而不是整份代码。
2. 第一次出现代码前，页面明确显示位置、输入、输出、忽略项和本步目标。
3. 默认代码片段不超过 10 个重点行；完整文件需要用户主动展开。
4. 用户可以完成至少四个微知识步骤，每步有即时解释。
5. 教学模式查看解释不会增加提示等级。
6. “这里没看懂”可以进入针对性补课并返回原位置。
7. 陪练提示才会增加依赖记录，且三层提示含义清楚。
8. 页面刷新后恢复准确教学步骤、回答和帮助状态。
9. 未完成教学桥梁时不能直接把用户判为能力不足。
10. 测试通过仍只形成候选证据；没有延迟变式复测时不能判定 L3。
11. Web/API 仍不执行 shell，只监听本机，固定沙盒路径校验不退化。
12. `npm run verify`、新增迁移测试、真实浏览器桌面与 360px 路径全部通过。

## 真人验收问题

工程验收后，让用户本人回答：

1. 你是否始终知道自己正在看哪个项目层？
2. 第一次看代码时，是否知道先看哪几行？
3. 哪个概念仍然让你卡住？
4. 教学是否太慢、太碎或仍然跳跃？
5. 进入编辑器修改时，是否知道第一步做什么？

未得到用户反馈前，只能写“引导式教学工程闭环通过，学习效果待真人验收”。
